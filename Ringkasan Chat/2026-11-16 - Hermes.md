## G480 "jalan sendiri" ternyata unattended-upgrades (21:05–21:07)

- User: G480 terlihat jalan sendiri, tidak bisa di-reboot (kirim foto layar). Penyebabnya: **update otomatis Ubuntu (`unattended-upgrades` / `apt-daily-upgrade`)** yang jalan sendiri habis boot untuk memasang update keamanan — itu yang bikin load mesin tinggi (1,7) dan status boot masih "starting" padahal sudah 29 menit nyala.
- **Reboot ditahan APT.** Layar menunjukkan `Operation inhibited by "APT" (PID 18329 "unattended-upgr"), reason is "APT is installing or removing packages"` — systemd tidak mengizinkan reboot selama APT memasang paket, supaya instalasi tidak terpotong. Solusi yang tertulis di layar: `sudo systemctl reboot -i` (abaikan inhibitor). Risiko kecil: kalau APT sedang di tengah memasang paket, instalasinya bisa terpotong; perbaikannya `sudo dpkg --configure -a` setelah boot.
- Unattended-upgrades adalah fitur bawaan Ubuntu Server yang menyala dari sananya, jadwalnya tiap hari, yang dipasang hanya update keamanan. Bisa dimatikan atau dijadwalkan ulang kalau user risih — belum diputuskan.
- User takut servernya di-hack. Penjelasan Bre: **server tidak terbuka ke internet** — tidak ada port forwarding (keputusan user 12 Nov), remote hanya lewat Tailscale (hanya perangkat sendiri), dashboard 9Router + Hermes hanya mendengarkan localhost (`127.0.0.1`). Update otomatis itu justru tameng, bukan ancaman.

## API gratis Xingchi: 9Router ditolak, OpenCode tembus (22:05–22:34)

- User dapat API gratisan dari Threads (tidak memasukkan data pribadi maupun kartu kredit) dan minta dicek sebagai custom provider di 9Router VPS. Hasilnya: itu **Xingchi API** (`api.xingchiapi.com`), sudah terpasang di 9Router VPS sebagai node `TERMUL` (koneksi `ocid` model `gpt-6.1-sol` + `ocid2` `gpt-4o-mini`, dipasang teman user).
- **Lewat 9Router: 403 `client_not_allowed`.** Provider hanya menerima client coding tertentu (Codex, Claude Code, OpenCode, termasuk Hermes Agent) dan menolak request dari script/SDK — request dari 9Router ditolak di gerbang ini. Langsung dengan identitas Hermes Agent gerbangnya lolos, tapi upstream tidak stabil (sekali "upstream temporarily unavailable", sekali timeout 60 detik; model `gpt-4o` tidak didukung akun ini).
- **Catatan keamanan:** nama model Xingchi di-spoof (misalnya `gpt-6.1-sol` bukan model OpenAI beneran) — jangan kirim data sensitif lewat sana.
- **Sambil mengecek, ketemu Hermes VPS sempat mati:** kunci di `~/.hermes/.env` tertukar dengan kunci Xingchi (67 karakter), jadi 9Router menolak Hermes (401). Koneksi Gemini di 9Router juga sempat mati lagi. Sudah diperbaiki dua-duanya: kunci 9Router dibalikkan, Gemini diaktifkan lagi, tes `2+2` keluar `4`, gateway di-restart dan log Connected to Telegram.
- File `config.json` yang dikirim user ternyata **bukan config provider — itu schema OpenCode** (template penjelas format config dari `opencode.ai/config.json`), tidak berisi provider, URL, maupun API key. Di VPS saat itu OpenCode juga belum terpasang beneran (hanya sisa data run lama, binary + `opencode.json` tidak ada).
- **OpenCode dipasang + dikonfigurasi (22:25).** User mengirim dua API key Xingchi (Key 1 "Ceds", dibuat malam itu 21:35, grup GPT公益 0.25x, status Active, tanpa expiry; Key 2 "Ocids Key") plus screenshot dashboard 9Router + Xingchi. Bre install OpenCode **v1.19.5**, menulis config `~/.config/opencode/opencode.json` (dua provider: `xingchi` pakai Key 1, `xingchi2` pakai Key 2, base `https://api.xingchiapi.com/v1`), dan mengetes: `opencode run -m xingchi/gpt-6.1-sol "2+2"` keluar **`4`**. Rute OpenCode ini yang tembus karena OpenCode ada di daftar client yang diizinkan Xingchi, sementara 9Router kena 403. Catatan: tes `xingchi2` (Key 2) sempat timeout 50 detik — belum terverifikasi Key 2 jalan atau tidak. Database OpenCode lama di VPS tidak cocok dengan versi baru, di-backup dulu ke `opencode.db.bak-old-2026-11-16` (session lama aman di backup).
- **Lambat, tapi jalan.** User merasa responnya lama sekali. Tes Bre: `gpt-6.1-sol` ~12 detik untuk 2+2, `gpt-6-astra` **48 detik**, beberapa request timeout. Penyebab: proxy gratisan (grup GPT公益 0.25x) — antre di belakang pengguna berbayar, kadang upstream penuh. Masih masuk kriteria user kemarin: lambat tidak apa-apa, yang penting jalan dan gratis. Kalau butuh cepat, pakai jalur Hermes lewat 9Router + Gemini (cepat, tapi jatah 20 request/hari); Xingchi/OpenCode jadi cadangan gratisan saat Gemini habis.
- Pemakaian sehari-hari dari VPS: jalankan `opencode`, pilih model `xingchi/gpt-6.1-sol` (pencet Tab di TUI), atau one-shot `opencode run -m xingchi/gpt-6.1-sol "..."`. Kalau masih muncul "free limit reached", berarti model default yang terpakai masih yang gratisan OpenCode — ganti dulu ke Xingchi.
